# Hero Section and Nav Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder hero and nav with the agreed design:
- a five-layer painted meadow that renders statically first, with the flowers fading in after the sky,
- then a subtle WebGL wind sway,
- phone-specific crops,
- the final copy layout,
- a fixed nav that turns solid and hides/shows, with a phone menu,
- an Open Graph image.

**Architecture:**
- **Pure TypeScript modules**, unit-tested with Vitest, decide:
  - where each art layer sits,
  - which image (size variant or phone crop) it loads,
  - how the nav state changes.
- **React components** render the static `<img>` layers from that data.
- **A framework-free WebGL renderer** draws the same layers with the wind shader on a canvas that takes over once everything has loaded.
- **Art pipeline:** a committed `sharp` script cuts masters and crops from `reference/hero/` once, and `vite-imagetools` makes the size variants at build time.

**Tech Stack:** what's already there, plus `vite-imagetools@12`, `sharp` (dev, for the script) and `vitest@5`. WebGL1, no 3D library.

**Spec:** `docs/superpowers/specs/2026-11-21-hero-design.md` (it builds on `docs/superpowers/specs/2026-11-20-portfolio-foundation-design.md`).

## Global Constraints

- **Layer stack, back → front:**

  | Layer id | Source file | Bend |
  |---|---|---|
  | `sky` | `reference/hero/4.png` | 0 |
  | `meadow` | `3.png` | 0.006 |
  | `stems-left` | `5.png`, art x 0–0.5 | 0.016 |
  | `stems-right` | `5.png`, art x 0.5–1 | 0.016 |
  | `cluster-left` | `2.png` | 0.011 |
  | `cluster-right` | `1.png` | 0.011 |

- **Art:** 2730×1536 (`ART_ASPECT = 2730/1536`).
- **Layout:**
  - **Wide** means hero width ÷ height ≥ `1.2`. Every layer covers the hero, anchored bottom-centre.
  - **Narrow** means the ratio is < 1.2:
    - `sky` still covers.
    - The other layers are scaled `0.72` and anchored at the bottom: `meadow` centre, `stems-left`/`cluster-left` left edge, `stems-right`/`cluster-right` right edge.
- **Phone crops:** full-height 45% strips at 864px wide, with pixel bounds in 2730-wide art:
  - centre `[751, 1979]` for `sky` and `meadow`
  - left `[0, 1229]` for `stems-left` and `cluster-left`
  - right `[1501, 2730]` for `stems-right` and `cluster-right`
  - A crop is used only when it covers the layer's visible part (within its clip).
- **Full variants:** 1280 / 1920 / 2730 px wide WebP at q80. Pick the smallest width ≥ the drawn width × min(DPR, 2), or else the largest.
- **Wind shader:** copy exactly from spec §5. The bend values above are the agreed "subtle" look. Do not retune.
- **Load order:**
  - `sky` first, with `fetchpriority="high"`.
  - Flower layers get their `src` only after the sky has loaded, then fade in (opacity, 550ms ease-out).
  - No fade when an image is already complete on the first check after its `src` is set, or when the visitor has reduced motion turned on.
- **WebGL takeover:**
  - The canvas is created only when all six images have loaded, reduced motion is off, and WebGL1 is available.
  - It crossfades in over 400ms after its first frame.
  - It runs only while the hero intersects the viewport and the tab is visible. DPR is capped at 2.
  - On context loss it's removed, and the static layers remain.
- **Copy:**
  - The `h1` stays "Rooted in the back end. Blooming on the front."
  - The sub line is "I'm Kerem, a full-stack engineer finishing my Software Engineering degree in Istanbul. I build with .NET, React and TypeScript."
  - Buttons: "See my work" → `#projects` (ink pill), "Get in touch" → `#contact` (62% white pill, ink border at 22%).
  - No availability pill.
- **Nav:**
  - Fixed, `NAV_HEIGHT = 64`.
  - Solid when `scrollY > 24`: `bg-cream/82`, `backdrop-blur-[10px]`, 1px bottom line at `ink/8`.
  - Hides on scroll down only when `scrollY > heroHeight − 64`, and shows on scroll up. It ignores movements of ≤ 2px and never hides while the menu is open or focus is inside the nav.
  - Phone (< 640px): name, Résumé pill and a menu button with `aria-expanded`/`aria-controls`, opening a card with the four `SECTIONS` links. The card closes on a link, Escape, an outside tap or the button.
- **Quality:**
  - Lighthouse mobile: Performance ≥ 90; Accessibility, Best Practices and SEO ≥ 95.
  - No horizontal scroll at 360px.
  - The copy is never overlapped by the nav and never clipped at 360×640, 390×844, 768×1024, 1280×720 and 1440×900.
  - A 390×844 phone downloads ≤ ~800 KB of hero art, with the sky ≤ ~100 KB.
- **Workflow:**
  - Work on branch `feat/hero`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing is pushed.
  - Every task ends with `npm test && npm run typecheck && npm run lint && npm run format:check && npm run build` green.

## Review Focus

1. **Rotating a phone or resizing across the 1.2 boundary:** images switch between crop and full. The canvas must never draw old textures in new rectangles. Expected: the art stays aligned; the renderer is rebuilt once the new images load. *(Task 5, Step 6)*
2. **Keyboard user tabbing while the nav is hidden:** focus entering the nav shows it. *(Task 2 tests; Task 6, Step 5)*
3. **Visitor with reduced motion:** no canvas, no flower fade, no nav slide; the page still looks complete. *(Task 7, Step 3)*
4. **WebGL context lost** (GPU reset, low-memory phone): the canvas disappears and the static meadow stays. *(Task 5, Step 6)*
5. **Cached revisit vs slow first visit:** on a revisit, flowers appear instantly with no fade. On a first visit the sky shows alone first, and the canvas never appears before all six images have loaded. *(Task 4, Step 5; Task 5, Step 6)*

```ts
export interface Size { width: number; height: number }
export interface Rect { x: number; y: number; width: number; height: number } // CSS px, relative to the hero
export interface ImageVariant { src: string; width: number; height: number }
export type Anchor = 'cover' | 'centre' | 'left' | 'right'
export type LayerId = 'sky' | 'meadow' | 'stems-left' | 'stems-right' | 'cluster-left' | 'cluster-right'
export interface CropDef { x0: number; x1: number; variant: ImageVariant } // x0/x1 = fractions of full art width
export interface LayerDef { id: LayerId; bend: number; anchor: Anchor; clip: readonly [number, number]; full: readonly ImageVariant[]; crop?: CropDef }
export interface Source { variant: ImageVariant; x0: number; x1: number } // full layer: x0 = 0, x1 = 1
export const ART_ASPECT = 2730 / 1536
export const NARROW_ASPECT = 1.2
export const NARROW_SCALE = 0.72
export const MAX_DPR = 2
export function isNarrow(size: Size): boolean
export function artRect(size: Size, anchor: Anchor): Rect
export function visibleSpan(size: Size, rect: Rect, clip: readonly [number, number]): [number, number]
export function chooseSource(size: Size, dpr: number, layer: LayerDef): Source
export function sourceRect(rect: Rect, source: Source): Rect
```

- **`artRect`:**
  - Cover width is `max(W, H·ART_ASPECT)`, and height is that width ÷ `ART_ASPECT`.
  - Wide, or `'cover'`: `x = (W − w)/2`, `y = H − h`.
  - Narrow and not `'cover'`: scale w and h by `NARROW_SCALE`, set `y = H − h`, and set `x` to `(W − w)/2` for `'centre'`, `0` for `'left'`, or `W − w` for `'right'`.
- **`visibleSpan`:** the art-width fractions inside `[0, W]`, intersected with `clip`.
- **`sourceRect`:** narrows `rect` horizontally to `[x0, x1]`.

### Task 5: WebGL wind renderer

**Files:**
- Create: `src/sections/hero/meadowRenderer.ts`, `src/sections/hero/windShader.ts`
- Modify: `src/sections/hero/Meadow.tsx`

**Interfaces:**
- Consumes: the `<img>` refs and the per-layer `Source` and `Rect` from Task 4.
- Produces:

```ts
export interface DrawLayer { image: HTMLImageElement; bend: number; rect: Rect; span: number; texClip: [number, number] }
// rect = sourceRect(...) in CSS px; span = source.x1 − source.x0;
// texClip = clip mapped into the source texture: [(clip0 − x0)/span, (clip1 − x0)/span]
export interface MeadowRenderer { setLayers(layers: DrawLayer[], size: Size): void; start(): void; stop(): void; destroy(): void }
export function createMeadowRenderer(canvas: HTMLCanvasElement, onFirstFrame: () => void, onLost: () => void): MeadowRenderer | null // null = no WebGL1
```

- **`windShader.ts`:** exports `VERTEX_SHADER` and `FRAGMENT_SHADER` strings. The fragment shader takes the uniforms `tex`, `t`, `bend`, `span`, `rect` (vec4, normalised to the canvas: x, y, w, h) and `texClip` (vec2). For each pixel:
  - `uv = (v − rect.xy)/rect.zw`; transparent outside `[texClip.x, texClip.y] × [0, 1]`
  - `h = 1 − uv.y`
  - `dx = wind(v.x + uv.y·0.15, t) · h·h · bend / span`
  - sample `texture2D(tex, vec2(uv.x − dx, uv.y))`
  - `wind` is copied exactly from spec §5
- **The renderer:**
  - blending `ONE, ONE_MINUS_SRC_ALPHA`; premultiplied upload; `CLAMP_TO_EDGE`, `LINEAR`
  - textures are uploaded from the `HTMLImageElement`s in `setLayers`; old textures are deleted
  - it resizes the canvas to `size × min(DPR, 2)`
  - `start`/`stop` control a `requestAnimationFrame` loop; time advances only while running
  - `webglcontextlost` calls `onLost`
